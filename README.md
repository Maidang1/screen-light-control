# Screen Light · Windows 屏幕控制台

Windows 中文屏幕与亮度控制工具。已按 Pencil V3 设计实现浅色界面、蓝色滑块、紧凑显示器卡片和分组设置，支持高 DPI 显示。

## 显示控制台（新增）

主面板底部和托盘菜单的「显示控制台」提供统一入口。保留原有每屏亮度、快捷键、平滑软件调光和校准功能。扩展以 Windows 公开接口和显示器明确提供的 DDC/CI 能力为边界，不安装驱动，不调用未公开接口。

| 能力 | 控制方式与范围 |
| --- | --- |
| 分辨率、刷新率、旋转 | 从当前驱动枚举有效模式；按屏幕选择与暂存 |
| 主屏、多屏坐标和排列 | 布局预览、物理像素坐标、从左到右排列；校验重叠和不可达的桌面区域 |
| 仅电脑屏幕、复制、扩展、仅第二屏幕 | Windows CCD 投影模式切换 |
| HDR / 高级颜色 | 驱动开放高级颜色接口时启用；不支持时禁用 |
| 显示器亮度、对比度、音量 | 按设备实际读出的范围设置，并读回核对；内置屏幕亮度仍使用原主面板的 WMI 通道 |
| 显示器静音、输入源、电源 | 仅能力字符串明确列出且读取成功时开放；输入源和电源需要在界面单独确认，不进入方案 |
| 显示方案 | 导出与导入 `.screenlight` 文件，按设备路径匹配，导入重新校验后试用 |
| 缩放、夜间模式、ICC 配置、辅助颜色滤镜、电源和显卡选项 | 提供对应 Windows 设置入口，由系统或显卡管理 |

**配置试用与恢复**：系统显示配置由独立工作进程保存原始 CCD 配置和高级颜色状态。应用前先验证；应用后必须在工作进程开始计时的 20 秒内点击「保留配置」，否则恢复原配置。关闭控制台、父进程退出或通信断开也会触发未确认配置的恢复。确认时再次检查期限，再保存 Windows 显示配置。控制台打开前会释放亮度工作进程，避免跨模式持有物理显示器句柄。

硬件 DDC 工作进程超时后可终止；承载显示试用的进程在通信失败时保留恢复职责，不直接杀死。恢复遇到临时驱动错误会重试。工作进程自身崩溃、驱动永久阻塞或设备拔出时，恢复可能无法确认，应在 Windows 显示设置检查当前配置；这不是能绕过硬件故障的保证。

方案文件包含显示器设备路径，用于稳定匹配；它不执行脚本，也不自动修改显示器输入源或电源。复制显示下如需逐屏编辑，先试用并确认扩展模式。输入源与电源的切换可能需要显示器实体按键恢复。

Windows 的部分功能没有稳定公开的第三方控制接口；显卡超频、HDCP、固件、链路带宽与厂商专属增强功能也不能由通用程序全部接管。设置入口是系统管理功能，不代表本程序已直接实现这些功能。

新增控制逻辑、方案校验和恢复状态机测试可在不改动硬件的情况下运行。Linux 上已验证通信、模型校验和控制台渲染；Windows CCD / HDR / DDC 调用仍需要在 Windows 实机上验证，不应把编译成功当作硬件验证通过。

## V3 界面

- 主面板：单屏紧凑显示，多屏独立卡片；窗口高度按屏幕数量调整，空间不足时显示器列表可滚动。预设、设置和恢复画面保留在底部。
- 右上角「滑块联动」直接保存联动偏好，只有一块屏幕时禁用；每张卡片的调节图标直达对应显示器设置。
- 设置分为「通用与快捷键」「显示器设置」，使用开关、模式单选和数值输入；底部保存和取消始终可见。切换显示器保留未保存的编辑，取消不修改现有设置。
- 软件模式中硬件校准输入禁用；保存时检查亮度范围，错误会显示在设置页并定位对应显示器。
- 诊断详情展示请求亮度、硬件读回、可用通道和当前方式，同时保留只读原始日志。
- 状态标签区分正在调节、硬件验证、自动回退、恢复和失败。标题栏及输入控件沿用 Windows 原生行为。

设计稿位于 `design-output/v3`；界面测试截图位于 `test-output/v3-*.png`。

## v3 新功能

- **全局快捷键**：`Ctrl + Alt + ↑ / ↓` 每次调节 5%，加 `Shift` 每次调节 1%；`Ctrl + Alt + Home` 立即清除所有软件调光。窗口关闭到托盘后仍可使用。快捷键被其他程序占用时会提示，详情可在设置和诊断中查看。
- **快捷键目标**：设置中选择鼠标所在屏幕、当前窗口所在屏幕或所有屏幕。所有屏幕快捷键按各屏当前值分别增减。
- **多屏滑块联动**：开启后，拖动任意滑块会将相同百分比应用到所有屏幕；默认关闭。相同百分比不代表不同显示器的实际亮度完全相同。
- **平滑软件调光**：约 180 毫秒过渡，连续操作以最新目标为准；恢复、退出及显示拓扑变化会取消旧动画。硬件背光仍按目标写入并验证，不高频发送渐变指令。
- **混合调光**：在卡片右上角菜单选择；20%–100% 对应校准后的硬件背光范围，低于 20% 时固定最低背光并逐步软件压暗。软件透光比例保留 10% 下限，不会完全黑屏。硬件失败仍回退纯软件调光。
- **每屏校准与记忆**：设置中选择显示器，可设置名称、模式、硬件最低/最高亮度和曲线（0.5–2.0，默认 1）。设置使用设备实例标识匹配，换接口后可能需要重新配置。
- **可选启动恢复**：默认只读取亮度；开启「启动时恢复上次亮度」后才会主动应用上次成功调节的值。软件调光退出时仍会清除。

设置保存在程序旁的 `settings.xml`，需要该目录可写；保存失败会在设置按钮和诊断中提示。便携 ZIP 不包含个人设置。恢复画面会取消待处理请求并清除覆盖层，已发送的硬件指令可能仍会完成，硬件背光不会被恢复按钮改回。

混合调光和校准参考了 MonitorControl，归属与 MIT 许可见 `THIRD-PARTY-NOTICES.txt`。本版本没有加入显示器音量、静音和对比度控制。

## 运行

双击 `dist/ScreenLight.exe`，将同目录的 `ScreenLight.exe.config` 一起保留。也可解压 `dist/ScreenLight-portable.zip` 后运行。需要 Windows 10 / 11 与 .NET Framework 4.7.2 或更高版本，无需安装其他运行环境。

- 拖动屏幕卡片中的滑块；方向键每次调节 5%，Shift + 方向键每次调节 1%。
- 「夜间 / 阅读 / 工作 / 明亮」预设应用到所有屏幕。
- 卡片右上角可切换自动模式、软件调光和混合调光；底部「设置」提供快捷键、多屏联动和每屏校准。
- 「恢复画面」清除所有软件调光，不会修改硬件背光。
- 关闭窗口后驻留托盘；托盘右键「退出」会清除软件调光并彻底退出。
- 插拔显示器或更改显示模式后自动重新检测，也可以手动点击「重新检测」。

## Windows 托盘运行

- 普通启动打开亮度面板；关闭或最小化后收起到通知区域，快捷键和软件调光继续运行。
- 左键点击托盘图标恢复面板；如果设置或显示控制台正在打开，会激活已有窗口。
- 右键菜单可打开显示控制台、设置、应用亮度预设、重新检测、恢复软件调光或退出。
- 需要启动时直接驻留托盘，可运行 `ScreenLight.exe --tray`。这不会短暂弹出主面板，也不显示任务栏按钮。快捷方式的目标后加 `--tray` 同样有效。
- 再次普通启动会激活已运行的窗口；再次以 `--tray` 启动不会打开窗口。托盘「退出」会先关闭控制台并处理未确认配置的恢复，再释放工作进程和图标。
- 不自动添加开机启动项。Windows 可能将图标放在通知区域的折叠菜单中，可在任务栏设置中调整显示。

## 两种调节方式

**自动模式**优先使用硬件亮度。内置屏幕通过 WMI；外接屏幕优先通过 DDC/CI VCP `0x10`，失败后尝试 Windows 高层显示器接口。发送指令后会等待并读回实际亮度，只有与目标一致才显示「硬件亮度已验证」。

如果接口报告成功但读回数值未变化，或硬件接口不可用，程序会自动切换到**软件调光**。卡片会明确显示软件模式。软件调光使用透明、鼠标可穿透、不抢焦点的黑色覆盖层改变画面明暗，不改变显示器背光或功耗。软件亮度最低为 10%，100% 清除覆盖层，退出程序自动恢复。它不能超过显示器本来的最大亮度；独占全屏应用、安全桌面等特殊画面可能无法覆盖。镜像显示的物理屏幕共享同一桌面区域，软件调光也会一起变化。

如果想使用真实背光调节，请在显示器菜单中启用 DDC/CI；也可以检查显示器的 HDR / 动态亮度模式是否锁定了背光。切换回「自动模式」后可重新尝试硬件调节。

默认启动和重新检测只读取硬件亮度，不会修改背光；显式开启启动恢复后例外。已启用的软件调光会在重新检测时保留；显示拓扑改变时先清除旧覆盖层。不添加开机启动项，不修改注册表，不联网。

## 驱动无响应保护

WMI、DDC/CI 和 Windows 显示器 API 现在统一在独立辅助进程内执行。旧实现虽然使用后台线程，但没有超时；驱动调用不返回时会一直占用 I/O 锁，导致检测、硬件调节、重新检测和退出持续等待。这是源码中确认的卡死风险，尚未在报告故障的电脑上验证具体驱动原因。

- 显示器检测限时 8 秒，单次硬件读写限时 3 秒（不含正常的读回重试间隔）。超时会终止辅助进程，避免后台任务继续占用硬件句柄。
- 检测失败时使用 Windows 逻辑屏幕信息提供软件调光；调节失败时沿用软件回退。每个逻辑屏幕使用独立辅助进程并行检测；一个屏幕超时只停用该屏幕的硬件通道，其他屏幕仍可调节。点击「重新检测」创建新的辅助进程。
- 同一逻辑屏幕的调节请求串行执行，不同屏幕在同一批调节中独立推进。物理显示器句柄只存在于辅助进程，主进程退出不再等待驱动销毁句柄。辅助进程监视主进程退出，防止遗留进程。
- 显示拓扑变化及休眠恢复事件使用 200 毫秒防抖，检测期间收到事件会排队再次检测；诊断按钮在检测和调节期间暂时禁用，避免读取正在修改的日志集合。

程序仍使用同一份 EXE，辅助进程不会显示窗口。测试新增永久阻塞、进程异常退出、硬件错误后的通道重试以及新进程恢复检查；真实驱动行为需在 Windows 故障电脑上进一步验证。

实现参考了 [ScreenTools](https://github.com/yosong-github/ScreenTools/tree/0c86f44486be838e348ca58946980ed8e18a0844) 的逐屏工作进程、故障后终止进程、显示变化防抖与休眠恢复处理。这里用 C# 与本地命名管道重新实现，继续保留原有亮度读回验证，避免将「接口已接受」当作「硬件已生效」。参考归属见 `THIRD-PARTY-NOTICES.txt`。

## 本次修复依据

在当前 AOC U27N3G6R4B / NVIDIA RTX 4060 Ti 环境中复现了：请求从 70% 改为 65%，`SetMonitorBrightness` 与 `SetVCPFeature` 都返回成功，但读回仍是 70%。旧版直接将请求值显示为「已应用」，造成调节成功的假象。

v2 增加读回验证和软件调光后，集成测试通过真实窗口鼠标消息操作滑块，验证自动回退、桌面白色测试区域从 255 变为 166、鼠标穿透、覆盖层不占据前台以及恢复后的像素回到 255。测试结束会清除软件调光并恢复测试中改变的硬件亮度。

## 构建与测试

```powershell
.\build.ps1
.\test.ps1
```

构建使用 Windows 自带的 .NET Framework C# 编译器，无需下载依赖。普通测试使用模拟显示器和屏幕范围之外的覆盖层，不修改真实屏幕亮度；覆盖假成功、延迟读回、通道回退、混合调光、校准曲线、设置保存、快捷键分发、联动、动画取消、退出清理和高 DPI 界面渲染。测试期间会短暂显示设置窗口。

真实窗口 / 硬件集成测试会短暂调节亮度并在结束时恢复：

```powershell
.\test.ps1 -Integration
```

只读硬件报告：

```powershell
Start-Process -FilePath .\dist\ScreenLight.exe -ArgumentList '--diagnose', 'diagnostics.txt' -Wait -WindowStyle Hidden
Get-Content -Encoding UTF8 .\diagnostics.txt
```

界面的「诊断详情」同时提供硬件通道、请求值和读回结果。`tools/probe_monitor.py` 是开发用的独立硬件探针，默认只读，显式传入 `--write-test` 才会短暂测试写入并恢复。应用本身不依赖 Python。

## GitHub Actions 自动构建与发布

推送到 `main`、向 `main` 提交 PR，或在 Actions 页面手动运行 `Build and release Windows EXE`，都会在 Windows 上运行测试并构建。成功后可在该次运行的 Artifacts 中下载 `ScreenLight-windows`，产物保留 14 天。

发布新版本时，创建并推送以 `v` 开头的版本标签，例如：

```powershell
git tag v3.0.0
git push origin v3.0.0
```

标签工作流通过测试和构建后，会自动创建 GitHub Release 并上传 `ScreenLight.exe`、`ScreenLight.exe.config`、`ScreenLight-portable.zip`、第三方声明和 README。建议下载便携 ZIP，解压后直接运行；单独下载 EXE 时需同时下载配置文件并放在同一目录。重新运行同一标签的工作流会更新该 Release 的同名附件。

发布使用 GitHub 自动提供的 `GITHUB_TOKEN`，无需配置额外密钥。普通分支构建和手动运行仅生成 Artifacts，不创建 Release。
